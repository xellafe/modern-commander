# Fase 3a "Rete": piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** sorgenti di rete nelle schede di Modern Commander:
- SFTP, FTP/FTPS e indici HTTP in sola lettura;
- elenco delle condivisioni SMB;
- gestore delle connessioni, con password nel Windows Credential Manager e impronte da confermare;
- importazione da WinSCP;
- CSP.

**Architecture:** la posizione di una scheda e le sorgenti e destinazioni dei job diventano `Loc`: un percorso Windows, oppure `<schema>://<id connessione>/<percorso POSIX>`. Il locale resta il codice di oggi. Per le sorgenti remote c'è un trait `Provider` sincrono, una sola implementazione per protocollo, a cui arrivano dal router `Vfs` sia i comandi del backend sia la coda. Tra due provider diversi (o tra locale e remoto) si copia con `vfs::transfer`, che scrive in un temporaneo e poi rinomina, con il fallback confermato dall'utente.

**Tech Stack:** come la fase 2 (Tauri 2, Rust, React 19 + TypeScript, Zustand, i18next, Vitest). Nuove crate, scelte dal piano e aggiunte solo con `cargo add`:
- `ssh2` per SFTP: libssh2 con backend WinCNG su Windows, niente OpenSSL;
- `suppaftp` per FTP/FTPS, con la feature rustls;
- `ureq` per HTTP, con rustls;
- `rustls` con il provider `ring` (non `aws-lc-rs`, che su Windows richiede cmake e nasm) e `rustls-platform-verifier`, per l'archivio dei certificati di Windows.

Feature nuove della crate `windows`: `Win32_Security_Credentials` e `Win32_NetworkManagement_NetManagement`.

**Spec:** `docs/superpowers/specs/2026-10-22-fase-3a-rete-design.md`, con lo spec generale `docs/superpowers/specs/2026-10-16-modern-commander-design.md` (§6.2, §6.7, §7.2).

**Interfaces:**
- Produces (`vfs::loc`):
  - `#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)] #[serde(rename_all = "lowercase")] pub enum Scheme { Sftp, Ftp, Ftps, Http, Https }`, con `Scheme::as_str(&self) -> &'static str`.
  - `#[derive(Clone, Debug, PartialEq, Eq, Hash)] pub enum Loc { Local(PathBuf), Remote { scheme: Scheme, conn: String, path: String } }`.
  - Serializzazione: `Serialize`/`Deserialize` come stringa via `Display`/`Loc::parse`. Il frontend continua a mandare stringhe.
  - `impl Loc`:
    - `pub fn parse(s: &str) -> Result<Loc, AppError>`
    - `pub fn join(&self, name: &str) -> Loc`
    - `pub fn parent(&self) -> Option<Loc>`

    - `pub fn volume_key(&self) -> String`
    - `pub fn as_local(&self) -> Option<&Path>`
    - `pub fn is_remote(&self) -> bool`
- **Regole:**
  - **Parsing:** `<schema>://<conn>/<path>`, con `conn` in `[A-Za-z0-9_-]{1,64}`. Il path è letterale UTF-8 (nessuna percent-decodifica), con `/` doppi ridotti e senza `/` finale salvo la radice `/`. Un `<schema>://<conn>` senza path vale `/`. Tutto il resto è `Local(PathBuf::from(s))`. Uno schema sconosciuto o un `conn` non valido dà `INVALID_REQUEST`.
  - **`volume_key` remoto:** `"<schema>://<conn>"`.
  - **`same` e `is_within` remoti:** confronto esatto (POSIX distingue le maiuscole).
  - **Locali:** si delega a `paths::{same_path, is_within, volume_key, normalize_lexical}`.

- **Produces (`vfs::transfer`):** `pub fn copy(vfs: &Vfs, src: &Loc, dst: &Loc, replace: bool, confirm_unsafe: &mut dyn FnMut(&Loc) -> bool, progress: &mut dyn FnMut(u64) -> bool) -> Result<(), AppError>`, con questo algoritmo:
  1. Se `dst` è locale e il suo nome non è valido su Windows (`fileOps`-equivalente nel backend: caratteri `<>:"/\|?*`, nomi riservati, punto o spazio finale), `INVALID_NAME` prima di creare qualsiasi cosa.
  2. `reader(src)` e `stat(src)`.
  3. Si apre il temporaneo `<nome>.<8 esadecimali>.mcpart` nella cartella di `dst` con `writer(tmp, create_new = true)`.
  4. Si copia a blocchi da 256 KiB, chiamando `progress(byte)`. Con `false`, il temporaneo si elimina e si restituisce `CANCELLED`.
  5. Si chiude. `set_meta(tmp, src.modified_ms, mode)`, dove `mode` è quello di `dst` se `dst` esiste ed è remoto; errori di `set_meta` ignorati.
  6. `rename(tmp, dst, replace)`.

  **Fallback:** se il passo 3 fallisce con `ACCESS_DENIED`, oppure se `dst` esiste e `caps.atomic_replace` è `false`:
  - si chiama `confirm_unsafe(dst)`;
  - con `true` si scrive direttamente con `writer(dst, false)`;
  - con `false` si restituisce `CANCELLED` senza toccare `dst`.

  Su qualunque errore dopo il passo 3, il temporaneo si elimina (best effort).
- **Produces (runner e plan):**
  - Un elemento con sorgente e destinazione locali passa per l'`Executor` come oggi, elevazione compresa. Tutti gli altri passano per `vfs::transfer::copy` e per le operazioni del provider.
  - `plan::stat`, `plan::read_entries`, `plan::file_target`, `runner::{exists, is_real_dir, is_dir_link, is_empty_dir, meta}` e `conflict::next_free_name` restano su `std::fs` per il locale e usano `Provider::stat`/`list` per il remoto.
  - `conflict::same_file` sul remoto è `Loc::same`.
  - **Move tra provider diversi:** copia più `delete` della sorgente. **Move nella stessa connessione:** `Provider::rename`.
  - **Collegamenti a cartella remoti** (`Stat.dir_link`): `UNSUPPORTED` con detail `reparse_point`, come in locale. **Collegamenti a file remoti** si copiano come file.
  - `RootedExecutor` e `job_roots` considerano solo le posizioni locali.
